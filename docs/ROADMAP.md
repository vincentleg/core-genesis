# Product Testing roadmap

## Working now

- First Brick mission produces an isolated, usable Python application and actual test report.
- Product Testing is accessible from the existing campus building.
- Three real local browser testers capture screenshots, task outcomes, JavaScript errors and input/authority checks. All three recorded cases passed.
- Synthetic audience campaigns support targets up to 100, with independent contexts and at most five calls per explicit batch. Five of the captured 100-target campaign are complete; 95 were not run.
- Reproducible browser failures enter a structured Engineering handoff. One audited-scaffold restoration may run before repeating identical browser cases and actual regression tests. No repair was necessary in the captured run.
- Actual browser outcomes are queued for Evolution Lab and carried into the next mission as workflow evidence. Independent development, held-out and regression gates still decide any promotion.
- Tunnel, OpenPersonaSimulation and Stagehand were reviewed. No proprietary Tunnel code is reused. Local Playwright supplies browser execution without another inference adapter or paid service.

## Next, after the submission milestone

1. Extend the small audited repair vocabulary to specific reproducible application defects, with source diffs and per-edit regression cases. Current restoration cannot fix arbitrary new bugs.
2. Add consistent revision comparisons against frozen browser tasks and synthetic criteria. Keep synthetic sentiment separate from behavioral outcomes and real customer research.
3. Run more explicitly approved batches if useful; never describe a configured target of 100 as 100 completed evaluations.
4. Evaluate stronger OS isolation and optional Stagehand/Nemotron compatibility only if they improve measured reliability without paid infrastructure.
5. Design a separate, consent-based real-user beta program and production identity/privacy review. Neither exists in this prototype.
